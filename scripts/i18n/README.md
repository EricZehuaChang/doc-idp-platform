# IDP zh/en internationalization

Runtime: `frontend/src/i18n/`. The browser preference `idp-lang` wins over the browser language; unsupported languages fall back to `zh`. Settings exposes the selector to every user; administrative sections retain their role guard. There is no account preference API.

## Adding messages

Use `useI18n()` / `$t()` at the rendering boundary. Store locale-independent codes or `{ key, params }` in pure helpers and persistent UI state. Make display dictionaries computed or resolve them when rendering. Preserve business data and protocol values. Use explicitly imported `I18nT` with named slots and `scope="global"` for mixed rich text. Escape literal `@` and `|` as `{'@'}` and `{'|'}` in both catalogs.

Add the source message to `frontend/src/i18n/locales/zh.json`, then run from the repository root, supplying `DEEPSEEK_API_KEY` through the environment:

```sh
.venv/bin/python scripts/i18n_machine_translate.py
```

The translator uses DeepSeek v4 flash, disabled thinking, JSON object output, and batches of 40. It fills missing English keys only, rejects changed placeholders/empty translations, and never embeds credentials. Existing translations are retained. Runtime dependencies for the script are the repository's existing `httpx` dependency.

## AST extraction workflow

For newly introduced hardcoded text:

```sh
node scripts/i18n_extract.mjs --collect
.venv/bin/python scripts/i18n_machine_translate.py --inventory scripts/i18n/inventory.json
node scripts/i18n_extract.mjs --apply
```

Review `manual-review.json` before applying. Templates use the Vue compiler AST and scripts use the TypeScript AST. Concatenation, interpolation, rich text, eager values, data keys/types and pure-function messages require manual decisions. Source hashes prevent applying a stale plan. English machine translations supply readable per-file slugs; collisions receive a stable suffix. Comments are preserved.

The checked-in manual review report documents the initial migration; its line numbers predate extraction. All reviewed exclusions were resolved; `remaining.json` records the final scan. Inventory, extraction plans and translation caches are generated by the commands above. The original one-time migration artifacts were archived in the project delivery record; edit locale JSON directly for future translations.

## Checks

```sh
node scripts/i18n_extract.mjs --scan
node --test scripts/i18n_extract.test.mjs
.venv/bin/python scripts/test_i18n_machine_translate.py
cd frontend
npm test
npm run build
```

Vitest checks exact zh/en key and placeholder sets, runtime language switching/storage/html lang, export headers, API code mapping, and actual mounted rendering of every message. Rich slots are cross-checked against their component declarations. The scanner excludes comments and only permits Chinese in `locales/zh.json`.

The build regenerates `app/webdist`, which the backend serves. Deploy the tested assets with the existing frontend-only release procedure, retain old hashed files for rollback, then atomically switch `index.html`. Existing user-entered names, document contents and extraction field names remain business data in their original language.
